## 范围

- S11：真实 MCP stdio client/server 协议桥、tool discovery、错误边界与子进程 teardown。
- S12：真实 Subagent、spawn-in-process、Worker Workflow 的 plain / structured child、资源上限与有界 cleanup。

关键边界证据：

- S11 public tool name 与 raw MCP name 分层；非法参数由 MCP server/protocol 返回 JSON-RPC `-32602`，`isError: true` 是 MCP tool-result failure。Fiber dispose 后工具注销且 fixture child process 停止。
- S12 provider 创建事务完成后，run 所有权转移给 holder；每个 run 都显式 dispose。worker thread / `node:vm` 只提供调度和终止边界，不是安全沙箱。
- S13 Context B 能从同一 JSONL Session 继续 Turn 2，但 observation cache 不持久化；首次 edit 得到真实 `FS_NOT_OBSERVED`，read 后重新审批才成功。
- S13 的 `../outside.txt` 与外指 symlink 都在 Approval 和 tool body 前拒绝；应用层 realpath containment 仍存在 TOCTOU 边界。

## pnpm 环境修复

原先 PATH 中的裸 `pnpm` 指向全局 10.4.0，而 Corepack / 项目固定 11.7.0，导致脚本内二次调用在 store v10 / v11 之间触发 modules purge 提示。执行 `corepack enable pnpm` 后：

- 仓库内 `pnpm --version`、`corepack pnpm --version`、`corepack pnpm exec pnpm --version` 均为 `11.7.0`。
- 一次 frozen install 与连续两次 `pnpm exec` 均不再出现删除 / 重建确认。
- Corepack shim 在没有 `packageManager` 的目录可选择自己的默认版本；课程可复现版本仍由仓库固定为 11.7.0。
